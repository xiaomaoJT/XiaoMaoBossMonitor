# 登录鉴权方案

> 目标：**没登录就不让看画面**（拦在哪一层按运行模式分，见第二章），且口令在整条链路上都不以明文出现。
>
> 涉及文件（本仓库内）：`src/config/auth.js` · `src/composables/useAuth.js` · `src/composables/sha256.js` ·
> `src/composables/useBackendEvents.js`（模式判据）· `src/components/LoginView.vue` ·
> `src/LoginGate.vue` · `src/App.vue`（`interactive` 开关）· `src/components/AboutSystem.vue`
>
> ⛔ 文中提到的 `server/auth.mjs`（服务端 nonce / 会话 / 失败锁定）属于**引擎侧**，不在本仓库，
> 所以本仓库只走**本地摘要校验**这一条路 —— `/api/auth/challenge`、`/api/login` 这些接口都不存在。
> 想把门禁提到服务端，需要接入引擎。
>
> **默认凭据是 `xiaomao` / `xmjt`**（`DEFAULT_AUTH`）。这个口令只用于第一次进去看，
> 换口令的方法见第七章。
>
> 本文同时覆盖**其它本地校验型口令**（遮罩解锁密码）—— 见第九章。

---

## 一、要解决什么（威胁模型）

| 威胁 | 本方案的处理 | 是否真的挡住 |
|---|---|---|
| 随手把大屏链接发给别人，谁点开都能看画面 | 未登录时看不到画面：前端模式**不挂载** `App.vue`，后端模式盖一层不透光遮罩（见第二章） | ✅ |
| 有人在局域网里抓包，拿到管理员口令 | 报文里没有口令，只有 `sha256(H1:nonce)` | ✅ |
| 抓到报文后原样重放一次 | nonce 一次性、2 分钟作废，同一条 proof 第二次被拒 | ✅ |
| 翻前端产物 / 控制台找明文密码 | 产物里只有摘要，没有明文口令 | ✅ |
| 拿到 `server/data/auth-sessions.json` 冒充登录 | 文件里只存 `sha256(token)`，换不出可用 token | ✅ |
| 翻前端产物找遮罩密码 | 产物与配置里都只有摘要（第九章） | ✅ |
| 老版本存下来的**明文**遮罩密码一直躺在配置里 | 载入时自动换算成摘要并删掉明文字段（幂等） | ✅ |
| 拿 `curl` 暴力猜口令 | 按 IP + 全局计数，5 次锁 60 秒 | ⚠️ 只提高成本 |
| 能开控制台的人改前端绕过门禁 | **挡不住**（前端门禁天然如此） | ❌ 刻意接受 |
| 弱口令的摘要被离线穷举 | **挡不住**（摘要就是可穷举的） | ❌ 需自己换强口令 |
| 局域网内的中间人改包 / 回放整个会话 | **挡不住**（明文 HTTP，没有 TLS） | ❌ 需上 HTTPS |
| 以为"退出登录 / 关掉页面"就等于把监控停了（其实后端还在跑） | 门禁按模式分流，退出确认与设置页文案都写明后果（见第二章） | ✅ |
| 钉钉加签密钥 / TG Bot Token 被看到 | **挡不住**，且**不能**用摘要 —— 它们要原样发给第三方 | ❌ 靠"别导出、别进版本库" |

**一句话定位**：它能保证「明文不外泄 + 报文不可重放」，但**不是**一个能对抗有心攻击者的鉴权系统。真正的防线是「别把端口暴露到公网 + 换强口令 + 需要时上 HTTPS」。

## 二、门禁拦在哪一层（两种运行模式）

**登录页"拦住的到底是什么"，取决于监测在不在这台机器上** —— 也就是 README 5.1 的那两种运行模式。
判据只有一处：`useAuth.readBackendMode()`，它复用 `useBackendEvents.backendOn()`（开关开着 + 填了地址），
跟顶栏那颗「后端模式 / 前端模式」徽标、"运行时长取后端还是取本页"用的是**同一条规则**。
别在这儿另写一份判断：三处一旦漂移，就会出现"徽标写着后端模式、登录页却把大屏拦在门外"这种说不清的现象。

| 运行模式 | 未登录时 | 退出登录时 | 为什么 |
|---|---|---|---|
| **前端模式**（本页就是监测本身） | `App.vue` **不挂载** —— 不是盖遮罩，是连组件都不实例化 | App 卸载（停轮询、释放解码器、停本地检测） | 放它进来，未登录的人就在消耗解码与 AI 算力；而且"退出登录"确实等于把监测停了 |
| **后端模式**（监测在常驻设备上跑） | `App.vue` **照常挂载**，登录页只是盖在它上面的一层**遮罩** | 大屏**不卸载**，只是重新被登录页盖住 | 采集与检测根本不在这台机器上：拦住 App 既省不下算力、又只会让人对着登录页白等。登录 / 退出 / 干脆不开这个页面，都不影响常驻设备（照旧检测、照旧推送） |

两条容易做错的地方：

- **遮罩必须压过大屏里的所有浮层**（`z-index: 700`）。低一点点，未登录的人就能从边上看见画面。
  判定方式是用**五个取样点做命中测试**，不是"看着挺黑的" —— 只测屏幕中心是验不出来的，
  设置抽屉弹在右侧，中心点根本不在它上面。
- **遮罩挡得住鼠标，挡不住挂在 `window` 上的键盘监听**。这就是 `App.vue` 那个 `interactive` 开关的由来：
  盖着遮罩时由门禁传 `false`，把 `M / F / R / E / Esc` 让给登录页。不这么做的话，未登录的人敲一下 `M`
  就把遮罩盖上了（他自己看不见），等真正登录进来第一眼是「已锁定」—— 排查起来极其费解。

模式在**进登录页时**（`restoreSession`）和**退出登录时**（`logout`）各重读一次：用户完全可能刚在设置里
动过「后端检测服务」开关，那时存的档才算数。所以退出时会按最新配置重新分流 —— 关掉开关再退出，大屏真的会卸载。

## 三、三层：存 / 传 / 比

```
① 存   口令不入代码、不入配置明文
        H1 = sha256("账号:密码")        ← 只有它被保存
        ├─ 前端内置默认：src/config/auth.js → DEFAULT_AUTH.passwordHash
        └─ 部署自定义：  server/config.json → auth.passwordHash

② 传   浏览器                                       后端
        │  GET /api/auth/challenge
        │ ─────────────────────────────────────────▶  发一枚随机 nonce（32 字节）
        │ ◀─────────────────────────────────────────  { nonce, algo, ttlMs } + 记进待用表
        │
        │  POST /api/login { username, nonce, proof }
        │  proof = sha256(`H1:nonce`)      ← 报文里没有口令
        │ ─────────────────────────────────────────▶  取用并**立刻作废** nonce
        │                                              自己算 sha256(`H1:nonce`) 对比
        │ ◀─────────────────────────────────────────  200 { token, expiresAt } / 401 / 423
        │
        │  之后每次打开页面：GET /api/auth/verify?token=…

③ 比   前端本地兜底（后端不可达时）也只比摘要：
        digestEquals(sha256("账号:密码"), DEFAULT_AUTH.passwordHash)
```

为什么要 `H1` 而不是直接 `sha256(明文)` 上线：把账号当盐（`账号:密码`），同一弱口令在不同账号下摘要不同；同时服务端存的也是同一个 `H1`，**两端共用一份摘要**，不需要任何可逆运算。

为什么要 nonce：没有它，`proof` 就是一个固定值 —— 抓到一次就能重放。加上一次性随机数后，`proof` 每次都不一样，且只能用一次。

## 四、会话

| | 勾选「保持登录」（默认） | 不勾选 |
|---|---|---|
| 前端存放 | `localStorage` | `sessionStorage` |
| 有效期 | 30 天 | 12 小时（关标签页即失效） |
| 服务端 | `server/data/auth-sessions.json`，只存 `sha256(token)` | 同左 |

- **落盘是硬要求**：本项目后端会自愈重启（一天好几次），会话只放内存等于每次重启都要重新登录。
  写文件用 `tmp + rename`；**落盘失败（Windows 上杀软可能锁文件）不影响本次登录**，只记进诊断。
- **离线容忍**：`/api/auth/verify` 若**连不上**（而不是明确回 401），沿用本地会话并标记 `offline`；
  若明确回 401/403（token 已作废 / 过期），清掉并提示重新登录。两种情况的处理是相反的，不能混。
- 退出登录：前端先清本地（一定退得掉），再通知服务端作废那枚 token（不阻塞界面）。

## 五、失败节流（两道独立的闸）

| 位置 | 计数 | 触发 | 效果 |
|---|---|---|---|
| 前端 `useAuth.js` | `attemptsLeft` 5 → 0 | 本地校验失败 | 冷却 60 秒，期间不提交 |
| 后端 `auth.mjs` | 按 `ip` + 全局各一份 | 摘要不匹配 | 第 5 次失败即锁 60 秒，返回 `423 + retryAfterSec` |

两条规则：**① 服务端明确否决（401 / 423）时，前端绝不再走本地兜底** —— 否则服务端的锁定会被本地校验绕过去；② 服务端锁定是**全局 + 按 IP** 双份，换 IP 也刷不掉全局阈值。

## 七、换账号 / 换口令

```bash
# 生成摘要（把 'xiaomao:新密码' 换成你自己的账号:口令）
node -e "console.log(require('crypto').createHash('sha256').update('xiaomao:新密码').digest('hex'))"
```

写进后端配置（推荐 —— 改完重启服务即可，不用重新构建前端）：

```jsonc
// server/config.json
{ "auth": { "username": "xiaomao", "passwordHash": "<上一步的 64 位十六进制>" } }
```

- 不配 `auth` 段 → 用内置默认（`src/config/auth.js`）。
- 老写法 `auth.password`（明文）仍能识别，但**启动日志会告警**，建议换成摘要。
- 想让新口令也覆盖"前端离线兜底"那一份，同时替换 `src/config/auth.js` 的 `DEFAULT_AUTH.passwordHash` 并重新构建。
- 已登录的设备不会被踢；要立刻让所有人重登：删掉 `server/data/auth-sessions.json` 并重启服务。

## 八、有意留下的边界

1. **前端门禁可被绕过**：能开控制台的人可以直接改前端逻辑。前端门禁的定位是"挡住随手打开链接的人"，真正的边界靠网络（别暴露到公网）。
   **后端模式下这一点更明显**：大屏就挂在登录遮罩底下跑着，把遮罩那个节点删掉就直接看到画面了。这是"只当遮罩"这个语义的必然代价，换来的是"退出/关页面都不影响常驻设备"。
2. **没有保护 `/api` 其余接口**：`/api/status`、`/api/config`、`/api/events` 等仍是裸接口。做这一步要同时给桌面端 / 小程序 / 轮询链路都带上 token（还涉及 `sendBeacon`、`<img>` 这类无法自定义头的请求），改动面大，暂未做。
3. **明文 HTTP**：局域网内没有 TLS。要防中间人必须自己上 HTTPS（反代 + 证书）。
4. **弱口令可被离线穷举**：`xmjt` 这种 4 位口令的摘要，本地跑一遍就是秒级。默认值是"能开箱即用"，不是"安全"。

## 九、其它本地校验型口令（遮罩密码）

**判据**：这个口令是"只在本机比一下"，还是要"原样发给别人"？

- 只在本机比 → 可以且**应该**只存摘要。这是本章处理的对象。
- 要发给第三方服务器 → **不能**摘要（摘要了就没人能用了）。见本章末尾的"不该动的那些"。

### 9.1 两处口令，一套原语

| 口令 | 存储位置 | 域（scope） | 摘要 |
|---|---|---|---|
| 登录口令 | `DEFAULT_AUTH.passwordHash` / `config.auth` | （用账号当盐） | `sha256("账号:密码")` |
| 隐私遮罩解锁密码 | `options.mask.passwordHash` | `mask-unlock` | `sha256("boss-monitor:mask-unlock:口令")` |

> **历史上的第三处已取消**：「加载内置配置」的访问口令（`HIDDEN_PASSCODE_HASH` / scope `hidden-config`）。
> 完整配置不再编译进产物，改成用户自己选本地 `.json` 载入（见使用手册 5.76）——
> 文件本身就是凭证，再叠一道能被离线穷举的摘要不增加任何实际保护。

两处统一走 `composables/sha256.js`：

```js
secretDigest(scope, 明文)          // → 摘要
secretMatches(scope, 明文, 摘要)   // → 是否匹配（内部走 digestEquals，定长异或不提前短路）
```

### 9.2 为什么要域分隔（scope）

不带 scope 的话，"遮罩密码"和"登录密码"如果碰巧写成同一个字符串，摘要就一模一样 ——
**在一处泄漏的摘要等于把另一处的口令也交出去了**。带上 scope 后两者互不通用，
探针里有一条专门断言这个（`跨域重放被拒`）。

### 9.3 遮罩密码：只写、不回显

配置里只有摘要，系统自己也反推不出原文，所以**界面上没有"显示已有密码"这回事**：

- 输入框的语义是"设一个新的"，留空 = 不改（不是清空）；
- 想清掉用旁边的「清除密码」按钮，状态片在「已设密码 / 免密码」之间切换；
- 没设密码（摘要为空）时点击屏幕即可恢复 —— **"免密码"状态绝不能做成进不去**，那是 bug 不是安全。

`secretMatches` 对"期望摘要为空"一律返回 `false`，把"没设密码就放行"这个**策略**留给调用方：
遮罩的策略是"点击即恢复"——"免密码"状态绝不能做成进不去。

### 9.4 存量明文的迁移

老版本把遮罩密码以**明文**存在 `options.mask.password`，并且用明文直接比较。迁移函数
`config/defaults.js → migrateSecretFields(options)` 负责换算成摘要并**删掉明文字段**。

- **幂等**：已是新格式直接返回 `false`，不动它。
- **不覆盖**：明文与摘要同时存在时保留显式摘要，不让陈旧明文覆盖用户后来设的新密码。
- **自洽**：明文字段为空时也会补一个空摘要，而不是留下 `undefined` —— 所以它**不依赖调用方先跑过
  `fillMissingOptions`**（后端那份配置就不走前端那套补默认值的流程）。
- **两个调用点，缺一就会出现"配置里的明文没人管"**：
  - 前端 `App.vue` 载入存档时（紧跟着一次 `writeStorage()`，否则纠正结果只活在内存里）；
  - 后端 `headless-monitor.mjs` 的 `syncPushMirror()`（覆盖"用户直接手改过 `config.json`"那条路，
    它也同时服务 `POST /api/config` 的入口）。

为什么必须**删掉**明文字段，而不是"向后兼容继续比明文"：
只要还留着一条"明文也能过"的分支，攻击面就等于没缩小 —— 老存档里那份明文会一直是可用的口令副本。

### 9.5 不该动的那些（重要）

下面这些**不是**本地校验型口令，摘要化会让功能直接失效，**不要顺手改**：

| 凭据 | 为什么不能摘要 |
|---|---|
| 钉钉加签密钥 `dingtalk.secret` | 要参与 HMAC 签名后发给钉钉，必须能拿到原文 |
| Telegram Bot Token | 要拼进 `https://api.telegram.org/bot<token>/...` |
| 企微 / 钉钉 Webhook 地址（含 access_token） | 要作为 URL 原样请求 |

它们的保护手段是**流程**而不是哈希：别提交进版本库、别用「导出配置」往外发、需要出网时走 HTTPS。

| 探针 | 结果 |
